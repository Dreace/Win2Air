# 构建与测试

## 共享构建与商店上传

仓库通过 `build-tools` 子模块复用 `Dreace/flutter-build-tools`。首次克隆后运行 `git submodule update --init --recursive`。

在仓库根目录执行，构建与上传分为独立步骤：

```powershell
./build-tools/scripts/build_windows.ps1 -Config .build-tools.env
./build-tools/scripts/upload_windows.ps1 -Config .build-tools.env
```

构建调用现有 CMake 入口，生成 Release MSIX 并核对清单版本，不会上传。上传只使用已有产物，不触发构建；版本或商店身份不匹配时直接失败。

在根目录被忽略的 `.env` 中配置 `MSSTORE_APP_ID`、`MSSTORE_PACKAGE_NAME`、`MSSTORE_PUBLISHER`、`PARTNER_CENTER_TENANT_ID`、`PARTNER_CENTER_CLIENT_ID`、`PARTNER_CENTER_CLIENT_SECRET`、`PARTNER_CENTER_SELLER_ID`。商店打包从这些变量生成清单身份及对应的资源索引，包由商店签名；本地安装验证仍使用开发身份和开发证书。不要提交凭据。首次提交须先在 Partner Center 创建并填写必需信息；共享上传脚本的成功条件是商店已解析对应版本并进入认证阶段。

本地回归不访问商店：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File build-tools/tests/windows_release.Tests.ps1
```

## 应用开发

串流设置提供“待机后断开”，默认“永不”，可选 1、5、15、30 分钟。从进入静音待机开始计时，超时关闭接收器连接并保留音频源监听；恢复声音后使用已保存的认证信息重新连接，断开期间的音频不补播。手动断开、切换或删除设备会停止监听。系统休眠时释放采集，恢复后继续等待声音。该选项依赖“静音后暂停”，不依赖网络故障的“自动重连”开关。

在 Windows 原生环境中使用 Visual Studio 2026、MSVC v145 和 Windows SDK 26100。App 依赖版本由 `packages.config` 和标准 NuGet `packages.lock.json` 管理。

统计图表使用 LiveCharts WinUI 2.0.4，由解决方案中的 C#/WinRT 组件提供。构建此组件还需要 .NET 10 SDK；运行需要 x64 .NET 10 Runtime。应用和音频处理仍由原生 C++ 实现。

直接打开 `win2air-app/Win2Air.sln`，选择 `Debug | x64`，将 `Win2Air` 设为启动项目，然后使用“本地 Windows 调试器”启动。解决方案构建会增量编译发送器 DLL、复制运行文件并生成本地化资源，无需先运行 App 构建脚本，也不会安装 MSIX。Debug 配置关闭优化并生成 PDB，可在 App 源码中设置断点。

首次使用需安装 Visual Studio 的“使用 C++ 的桌面开发”和 C++ CMake 工具、对应 Windows SDK，并还原解决方案的 NuGet 包。`NuGet.Config` 将包放在 `out/packages`。发送器继续使用项目固定的原生 MinGW 工具链和已准备的静态依赖；默认依赖路径沿用 CMake preset，也可通过环境变量 `WIN2AIR_DEPENDENCY_PREFIX` 或 MSBuild 属性 `Win2AirDependencyPrefix` 指定。缺少依赖时构建会明确报错，不自动更换工具链。

Visual Studio 本地调试器调试的是 MSVC 编译的 App。发送器 DLL 由 MinGW 编译，保留独立 C ABI；其 GCC 调试符号不能当作 MSVC PDB 使用。跨入发送器源码调试需要相应的 GDB 工具，App 的 F5 调试不依赖这一步。

从仓库根目录执行：

```powershell
cmake -P win2air-app/scripts/build-sender.cmake
cmake -P win2air-app/scripts/build-app.cmake
cmake -P win2air-app/tests/run-offline.cmake
```

命令行入口与 Visual Studio 使用同一个 MSBuild 运行文件准备目标，并检查 SDK 的 C ABI。完成后可直接运行 `out/bin/Debug/Win2Air.exe`，无需安装 MSIX。Release 使用 `-DCONFIGURATION=Release`。

离线测试使用内存音频端点、受控采集后端和虚拟接收器，执行生产采集线程、软件 MFT、队列、端点恢复及串行会话逻辑；协议探测测试只连接本机回环地址。无需声卡、局域网接收器、交互桌面或 MSIX 身份，默认入口不枚举或修改真实音频端点，也不启动界面。软件 MFT 需要 Windows Media Foundation 组件。

应用构建后可运行语言资源内存回归。测试在控制台加载同一套资源运行库，执行生产文案查询、切换中英文并检查缺失键；预热后连续查询一百万次，并分别使用中英文界面语言执行两万次 DirectWrite 文字排版，每组私有内存增长上限为 2 MiB。此测试不创建窗口、不截图，也不连接接收器。

```powershell
cmake -P win2air-app/tests/run-resource-memory.cmake
```

图表内存回归需要交互桌面，运行 `cmake -P win2air-app/tests/run-chart-memory.cmake`。测试创建独立图表窗口，执行一万次相同数据更新及六千次带绘制的刷新，覆盖时间范围、指标、主题和数据缺口切换；另以空数据执行五百次隐藏/显示，检查页面切换保持图表加载状态。测试记录预热后的私有内存与回收后的托管内存，不截图、不连接接收器；测试中的主动 GC 仅用于测量存活对象，应用本身不主动 GC。此压力测试不能替代完整应用的长时间运行验证。

连接状态下的界面内存回归使用 `cmake -P win2air-app/tests/run-connected-memory.cmake`，需要交互桌面。测试复用本次原生构建的页面与协调器对象，通过虚拟采集后端和虚拟接收器传送音频，持续采样并往返切换播放页、统计页，报告内存和旧数据行的存活情况；不会访问真实接收器、声卡或截图。

CI 可只构建控制台测试：

```powershell
cmake -DTESTS_ONLY=ON -DCONFIGURATION=Release -DDEPENDENCY_PREFIX=<原生依赖前缀> -P win2air-app/scripts/build-app.cmake
cmake -DCONFIGURATION=Release -P win2air-app/tests/run-offline.cmake
```

仓库工作流在带 `win2air` 标签的 Windows x64 自托管 runner 上执行 Debug/Release。runner 需预装上述工具链、CMake、Ninja、jq、clang-format、软件 Media Foundation，并在检出目录准备 SDK 的固定 MinGW 工具链；原生依赖前缀通过仓库变量 `WIN2AIR_DEPENDENCY_PREFIX` 指定。无需真实设备或音频驱动。界面启动、端点驱动兼容性与真实接收器听音是另行授权的人工验证，不属于此自动测试入口。

需要 MSIX 时，为 App 构建增加 `-DPACKAGE=ON`。包版本使用源清单中的版本，日常测试无需修改。确需安装验证时使用 `-DVALIDATE_INSTALL=ON`；首次安装前，在管理员 Windows PowerShell 中执行 `win2air-app/scripts/trust-development-certificate.ps1` 信任本机开发证书。开发私钥位于被 Git 忽略的 `out/private/`，发布签名需单独配置。

C++ 使用 `.clang-format` 的 Google 样式。编辑器可启用保存时格式化；单文件执行 `clang-format -i <文件路径>`。离线入口自动检查全部 App 源码和测试的格式。

C++ 主程序复用 WinRT 预编译头，主程序和控制台测试各使用四路编译。Release 发送器使用独立的 `windows-app-dll-release` 预设并移除调试段；Debug 保留调试信息。未使用的机器学习初始化已关闭，安装包排除 ONNX Runtime、DirectML 和机器学习组件。WinUI、Skia 和图表所需依赖继续随包提供。

资源索引按配置及运行方式分别缓存；语言资源、框架 PRI 或构建脚本变化时重新生成。验证精简包中的图表依赖可运行 `Win2Air.Tests.exe --statistics-executable <payload/Win2Air.exe绝对路径>`；该入口使用隔离设置打开统计页，检查双图表加载后退出，不截图、不安装、不连接设备。

播放页提供当前设备的音量、静音和连接控制。当前设备控制等待接收器响应后才保存并显示已应用；连续拖动保留最新输入并合并提交。非活动设备只保存偏好，不建立连接。收藏设备优先，隐藏设备可通过“显示隐藏的设备”恢复显示，隐藏不会停止当前投送。选择另一个接收器会先结束旧会话，清理失败时显示错误并阻止创建新会话。

接收端管理可修改名称、收藏、隐藏和自动连接偏好。修改地址需要先断开，公开探测确认身份一致后才保存。删除设备会停止该设备会话并撤销配对凭据，失败保留设备记录和具体错误，旧授权不会继续复用。启动时只恢复已选接收器：启用恢复上次投送，或该设备的自动连接偏好时，会使用保存的音频源、音量、静音和初始呈现配置。健康数据尚未测量时显示未知。

设置页的“中断后自动重连”默认开启。网络中断、接收器连接丢失和源暂时不可用时，按 2、5、10、30、60 秒间隔重试，随后保持 60 秒；成功后复位。恢复等待保留本地静音控制，恢复时重新采集当前声音，不回放旧队列。指定源被移除后等待原设备恢复，不改用默认设备。设备卡片和托盘显示故障原因、恢复状态及下次重试倒计时。断开会抑制本次运行的自动连接；切换、禁用自动重连或退出会取消等待及在途重试。重新开启开关不会撤销已取消的连接意图。

系统睡眠时停采集并结束旧协议会话，唤醒后恢复仍有效的连接意图。网络接口变化触发相关目的地重建，已知无关接口不影响现有连接。认证失效和不支持的能力停止自动重试；需要配对时在当前页面弹出输入窗口，失败后可在窗口内重试，显式配对不复用旧凭据。自动连接始终只面向已选设备，不轮流连接保存列表。

统计页默认显示发送码率与估算延迟曲线，每张图都能独立选择内容和时间范围，也可查看发送数据量、发送包数量及重传速率。一分钟范围按秒汇总，十分钟范围按十秒汇总，一小时范围按分钟汇总。数据量和包数量显示周期增量，延迟显示周期平均目标预算；缺失采样显示断点，目标预算不代表实测声学延迟。右侧显示网络与其他数据，连接事件使用整行宽度。自适应会话在每次连接时重新读取接收端报告，不使用历史预算代替当前响应。

设置页可选择自适应、极低、低、均衡、稳定或自定义延迟。自定义延迟须为 20–5000 ms 的整数。已连接时更改延迟模式或自定义数值会断开并重新连接一次；保存失败时保持当前连接。

“极低”为固定 80 ms，“低”为固定 120 ms，均衡为 1000 ms，稳定为 2000 ms。自适应从 120 ms 起按 10 ms 一档调整，也可从已保存的档位继续。10 秒内累计至少 3 次重传请求后升到下一档；连续 30 秒稳定发送且没有重传后降一档，不低于本次连接的起始档。降档后 10 秒内再次升档时，锁定本次连接的自动回落；锁定期间仍可继续升档。重新连接后重新判断。自动调整保持当前连接。

自定义延迟使用滑块和数字输入，保存后生效。输入须为 20–5000 的整数。低预算采集使用有界队列，包立即消费，实际音频周期超出预算时明确报告。

静音待机可选择 10、30、60 秒或永不。持续静音时暂停 PCM 发送，保持会话、本地静音接管与音频源观察；有效声音满足连续相邻窗口判定后，释放旧音频并恢复当前内容。源错误会显示具体失败。低电平内容按实际声道 RMS 判断，定时器只推进超时。最终断开或退出恢复本地端点接管前的状态。

默认离线入口同时执行实际回环协议控制、虚拟采集/MFT/接收器、静音窗口、标记误差及失败回滚检查。已取得可信且采用同一时间基准的源与输出标记后，可以单独分析时间差：

```powershell
./win2air-app/out/tests/Debug/Win2Air.Tests.exe --measure-presentation <源标记ns> <输出标记ns> <基本预算ms> <设备补偿ms> <测量不确定度ns> '<测量方法>' '<源与输入描述>' '<设备型号及固件描述>'
```

该入口只分析调用者提供的已对齐标记，不采集或连接设备，不自行证明标记来源。偏差与不确定度合计须不超过 10 ms；时间基准不同、缺标记或精度不足不能算补偿验证通过。实际听音和声学测量需单独授权，软件时间关系校验不替代它们。

播放页显示 Windows 当前媒体会话提供的标题、艺人、专辑及封面；浏览器没有提供的字段保持隐藏。连接后通过现有控制通道发送媒体信息，切换或关闭媒体会话时更新或清空接收端内容，重连后重新发送。封面仅接受大小不超过 1 MiB、尺寸受限的 JPEG 或 PNG。媒体读取或接收端拒绝不会伪装成音频投送成功，错误显示在媒体区域。

接收端音量通过认证事件及定期音量查询更新，界面与托盘共享观察结果，不把反馈再次作为音量命令发送。不支持音量查询的接收器会停止后续查询；实际支持情况取决于接收器实现。

接收器型号与厂商别名随源码内置，无需本地数据源目录。新增规则时更新 `src/Discovery/ReceiverModels.inc` 和 `ReceiverBrands.inc`，保留厂商限定、排除空型号，并补充解析回归测试。型号名称只用于显示，不代表协议能力已验证。

窗口默认关闭到托盘，继续使用当前投送服务；左键单击托盘图标立即打开并置前主窗口，右键打开当前设备与音量浮窗，可切换设备、断开、打开主窗口或退出。选择“退出”会保存窗口位置并停止采集和会话；取消“关闭到托盘”后，关闭窗口也会退出。系统重建任务栏时会重建图标，窗口位置按当前屏幕工作区和 DPI 调整。

同一用户和应用身份只运行一个主实例。再次启动将命令转发到主实例，不创建另一条采集链。命令支持 `--open playback|statistics|settings`、`--connect <设备身份>`、`--disconnect`、`--minimized`；连接和断开不能同时指定。已安装包支持 `win2air://open/playback`、`win2air://open/statistics`、`win2air://open/settings`。

统计页每秒更新发送包数、字节数、重传、采集帧数、队列占用及健康原因。历史可查看最近一分钟、十分钟或一小时，断开和缺失样本显示断点。会话计数与应用累计分开显示；没有可信观察的接收端时钟、播放欠载及声学延迟显示不可用。已观测的恢复、重传或队列劣化仍会降低健康等级，改善需要持续十五秒。

选择“导出诊断”后保存为新的 ZIP 文件；导出在后台执行，可以取消。包内包含安全事件日志、系统信息、接收器公开状态、指标历史、普通偏好和清单，使用标准 ZIP 校验。认证秘密、配对材料、音频和私有目录不在导出范围。检测到敏感内容、超过 100 MiB、写入失败或取消时明确失败并清理临时文件。未打包运行时，清单将包版本标记为不可用。

常规设置中的日志级别即时生效并保存。未手动选择时，Debug 使用 Debug，Release 使用 Info；普通设置保存不会把构建默认值固定下来。连接、实际待机、恢复、自动重连、来源切换和自适应调整在事件发生处记录，调试采样保留为 Debug。接收端媒体控制分别记录排队和执行结果。异常详情最多保留 4096 字节并拆成有界记录，JSON 字符经过转义；日志过滤发生在文件写入前。技术错误详情保留在日志中，日志本身无法写入时使用调试输出。

登录启动默认关闭，可在设置中申请启用；只有系统接受且偏好保存成功才显示已应用。系统或用户禁用时显示具体状态，不绕过系统策略。直接运行未安装的构建产物可以使用托盘和单实例，但登录启动显示不可用。登录启动的最小化与恢复上次投送可分别设置；恢复失败保留错误，不显示已开始播放。

主导航提供播放、统计、设置。播放页集中显示当前接收器、连接状态、投送音量和候选设备，底部音频源摘要可进入音频设置。设置分为常规、音频、串流和接收端管理；手动添加、配对、名称和地址编辑位于接收端管理。自定义预算只在选择自定义模式时显示。常规设置提供跟随系统、浅色和深色主题，以及跟随系统、简体中文和英文界面；系统语言不受支持时使用英文。主题、语言和托盘文案使用同一偏好，提交期间显示等待，成功写入后才显示已保存。音频设置可跟随默认输出或指定音频源，并设置电脑也播放；指定源不可用时明确报告不可用。

设备管理可恢复隐藏的接收器，设备名称旁显示稳定身份以区分同名设备。“遗忘配对”停止该设备会话并撤销授权，保留名称、收藏、音量和其他公开偏好；“删除设备”还会移除公开记录。本地音频恢复或授权文件删除失败时显示具体错误，仍尝试持久撤销旧授权，设备记录保留供重试。撤销标记成功写入后，即使旧文件仍在，重新启动也禁止导入旧授权；重新输入配对码并成功保存新的授权后才能解除该标记。

没有设备时，可直接选择提示旁的添加入口，填写地址和整数端口。配对区域显示所选设备，输入配对码后可直接连接或按 Enter 提交。删除设备、清除配对都会先显示后果确认，默认取消。

需要选择“应用”的设置会保留未提交的输入，其他选项保存和切换语言不会覆盖草稿。预设延迟模式直接使用预设预算；切回自定义时保留原输入。

实机入口 `tests/hardware/run-app-validation.cmake` 需要明确授权及 `ENABLE_HARDWARE=ON`，并提供目标、音频输入和包身份。实际播放还需听音确认；缺设备或确认时不能视为通过。构建产物和默认临时测试数据位于 `out/`。

在已解锁的 Windows 桌面验证编译后的界面，可使用以下入口。路径须为绝对路径；此入口使用独立设置，依次访问播放、统计、设置并返回播放，不连接真实接收器。截图、运行报告和隔离状态保存在指定的截图目录；日常设置保持独立。截图用于人工检查，离线 CI 测试仍通过虚拟设备执行。

```powershell
./win2air-app/out/tests/Debug/Win2Air.Tests.exe --gui-flow-executable <Win2Air.exe绝对路径> <截图绝对路径.png>
```

商店图把真实窗口设为 1920×1080 并使用模拟播放数据，依次截取简体中文与英文的播放、统计、设置页。设置页停留在常规分区，主题为浅色，导航栏保持展开。输出为 `zh-CN-playback.png`、`zh-CN-statistics.png`、`zh-CN-settings.png`、`en-US-playback.png`、`en-US-statistics.png`、`en-US-settings.png`。命令会先确认 Win2Air 未在运行，再编译应用和测试；截图期间使用独立状态目录，不读取、不修改日常设置。桌面必须已解锁。

```powershell
cmake -P win2air-app/scripts/capture-store-screenshots.cmake
```
